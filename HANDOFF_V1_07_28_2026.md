## 2. HARD PLATFORM CONSTRAINT - DO NOT RE-LITIGATE

**Galaxy Watch 7 (SM-L310) runs Wear OS 6** (Android 16 / SDK 36 / One UI Watch 8.0).
Verified via `adb shell getprop`.

Wear OS 6 **blocks programmatic watch faces**. A Kotlin `WatchFaceService` installs and
registers correctly but is refused by the system. Confirmed in this device's own logcat:

```
WearServices: [WFInfoResolver] Blocked watch face
  WatchFaceId[com.reddoor3.forexdial, com.reddoor3.forexdial.wear.ForexDialWatchFaceService]
```

**Watch Face Format XML is the only option.** The dead Kotlin renderer still exists at
`wear-app/src/main/java/com/reddoor3/forexdial/wear/ForexDialWatchFaceService.kt` for
reference but is no longer registered in any manifest. It can be deleted.

**Watch Face Studio (WFS) is NOT Watch Face Format (WFF).** WFS is Samsung's GUI tool and
has real limits (no conditions, no SMALL_IMAGE in circle slots). Hand-written WFF XML
supports `<Condition>` / `<Expressions>` / `<Expression>` / `<Compare>` / `<Default>`
since Wear OS 4. Dynamic colours driven by battery percent or complication values ARE
achievable. Do not repeat the "WFS can't do conditions, therefore this is impossible"
conclusion - it does not apply to hand-written WFF.

## 3. THE FOUR-FILE RULE (this cost an entire session)

`res/raw/watchface.xml` **alone is not enough.** A WFF module needs all four:

| File | Purpose |
|---|---|
| `res/raw/watchface.xml` | The face content itself |
| `res/xml/watch_face.xml` | Just `<wallpaper/>` |
| `res/xml/watch_face_info.xml` | Declares the preview drawable |
| `res/xml/watch_face_shapes.xml` | **Points at the raw file.** The critical one. |

Plus `res/drawable-nodpi/preview.png` and `preview_circular.png`.

Without the `res/xml/` trio, the face installs, Samsung logs `dwf watchface Info`, and
Google's resolver silently refuses it with:

```
WearServices: [DeclarativeWatchFaceResolver] Declarative watch face in package
  com.reddoor3.forexdial.face could not be parsed - Resource ID #0x0
```

That message is a **reference** failure, not a parse failure, despite the wording.

`watch_face_shapes.xml` content:
```xml
<WatchFaces>
    <WatchFace file="@raw/watchface" width="450" height="450" shape="CIRCLE"/>
</WatchFaces>
```
`width`/`height` MUST match the `<WatchFace>` element in `res/raw/watchface.xml`.

`watch_face_info.xml` attributes are **NOT namespaced** - plain `value=`, not
`android:value=`.

### Ruled out by direct test - all irrelevant
- `classes.dex` in the bundle (AGP injects one even with zero dependencies; harmless)
- Format version (1, 2, 3, 4, 5 all behaved identically)
- Canvas size (450 vs 480)
- XML declaration and comments in the raw file

### How it was found
`adb pull` the WFS-built face already working on the watch
(`com.watchfacestudio.md307digital`), then `aapt2 dump resources` and
`aapt2 dump xmltree` on both APKs and diff the resource tables.
**When a sideloaded thing won't appear, diff against a working artifact on the same
device before touching your own build.**

adb -t <ID> shell screencap /sdcard/s.png

Then Read the PNG. Two traps:
- Do NOT use `adb exec-out screencap -p > file.png` in PowerShell. The `>` redirect
  inserts a BOM and corrupts the binary.
- Do NOT run the `/sdcard/...` paths through Git Bash. MSYS rewrites them to
  `C:/Program Files/Git/sdcard/...`. Use PowerShell for these, or `MSYS_NO_PATHCONV=1`.

### Gotchas
- **The watch registers TWICE on ADB over mDNS.** Plain `adb install` fails with
  "more than one device". Get the transport id from `adb devices -l` and use `adb -t <ID>`.
- Android Studio's Run button was executing `:wear-app:testDebugUnitTest` (unit tests,
  no deploy) for much of the prior session. Build from the command line instead.
- If Gradle reports `compileDebugKotlin UP-TO-DATE` after a real source change,
  delete the module's `build/` directory.
- PowerShell 5.1 mis-parses non-ASCII punctuation (em-dashes) in scripts, and
  `Set-Content` round-trips can corrupt them in source files. Keep scripts ASCII.
- `.NET` `ZipFile.CreateFromDirectory` on PS 5.1 writes Windows backslashes into zip
  entry names and `CompressionLevel::NoCompression` still emits Deflate. If ever
  repackaging an APK by hand, use the JDK `jar cfM0` instead.

### Complication slots - READ BEFORE ADDING ANOTHER
Limit is **8**, now confirmed from the XSD (`maxOccurs="8"`).
A malformed slot **crash-loops the watch face runtime** and blanks the watch;
Android reschedules it 30 minutes out. Recover immediately with
`adb shell am force-stop com.samsung.wear.watchface.runtime`.
Diagnose with `adb logcat -b crash -d`.
Use `primaryProvider` (NOT `defaultProvider`), include the required
`defaultSystemProvider`/`defaultSystemProviderType`, and make sure the fallback
type is present in `supportedTypes` (e.g. `"SMALL_IMAGE EMPTY"`).

**The XSD is the source of truth, not the prose docs** - those gave wrong
attribute names twice. Fetch from
`raw.githubusercontent.com/google/watchface/main/third_party/wff/specification/documents/1/`

### Architecture for the hard elements
Complication services **still work on Wear OS 6**. They are Kotlin and can render
arbitrary bitmaps. So: **Kotlin draws the complex parts as `SMALL_IMAGE` bitmaps,
WFF just places them.** That recovers nearly all the pixel control the blocked canvas
renderer would have given - coloured pip digits, session circles, battery candle.

All 11 complication services already exist in `wear-app` and are registered.

Slot budget is **8** (needs re-verification): EUR/USD image, pips bar, DXY, BTC, yield,
and three session circles. Battery and time are built-in WFF data sources and cost
no slot.
